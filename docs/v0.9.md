## Pruebas ejecutadas y superadas

### Fase B

- 16 fichas, 16 posiciones únicas y puntos de interacción libres de colisiones.
- Alcanzabilidad de todos los NPC desde la entrada mediante una búsqueda sobre
  la malla de colisiones del juego, sin atravesar mesas ni paredes.

### Integración gráfica (Chromium real, automatizado)

- Escritorio 1100 × 850 y móvil emulado 390 × 844, este último con densidad 2.
- 16 PNG cargados con dimensiones correctas y catálogo sin IDs repetidos.
- 3.360 equipos ordenados distintos (16 × 15 × 14), identidad visual correcta,
  incluyendo equipos con clases repetidas.
- 48 comprobaciones de dibujo (16 héroes × 3 puestos): PNG correcto, escala,
  proporción, límites, suavizado desactivado y transparencia al caer.
- Capturas de seis equipos que cubren todos los héroes en escritorio y móvil:
  revisión visual de siluetas, orientación, anclajes, espaciado, nombres y flecha.
- Fallo simulado de `david.png`: advertencia, reserva y juego operativo.
- Ninguna imagen rota ni excepción JavaScript en las cargas normales.

### Regresión

- `node tests/animations.cjs`: cuatro animaciones de cada enemigo, prioridades,

- Sintaxis de todos los JS/CJS y `git diff --check` sin errores.

### Límites de validación

No se ha probado en Safari, Firefox, iPhone/Android físico ni en un despliegue
remoto de v0.9, porque no se ha autorizado publicación. Móvil emulado no equivale
a dispositivo físico. La partida de estadísticas normales usa azar determinista;
no implica que todas las composiciones ganen ni modifica el balance original.

## Repetir pruebas

```sh
node tests/animations.cjs
npm install --no-save playwright
npx playwright install chromium
node tests/regression.cjs
node tests/adventurers.cjs
```

La primera orden ejecuta pruebas de lógica sin dependencias; las dos siguientes
instalan Playwright y su navegador para desarrollo; las dos últimas ejecutan las
pruebas en navegador. `BROWSER_PATH` permite elegir otro binario Chromium local.
No subir `node_modules` ni los archivos generados por npm.

## Subida manual

1. Crear una rama desde `main`, por ejemplo `feature/v0.9-aventureros`.
2. Descomprimir el ZIP y subir su contenido manteniendo las carpetas `js/`,
   `assets/personajes/`, `tests/` y `docs/`; `index.html` va en la raíz.
3. Revisar que el diff solo incluya los 24 archivos enumerados. No eliminar
   carpetas existentes ni reemplazar `assets/enemigos/`.
4. Probar la rama y abrir una PR hacia `main`. Fusionar únicamente cuando se
   decida publicar. GitHub Pages seguirá el flujo que ya tenga configurado.

Los cuatro archivos de código y los 16 PNG deben publicarse juntos para evitar
que una versión del cargador apunte a recursos todavía ausentes.
